# fishfishfish · 我的海洋

文档版本：0.8 · 日期：2026-10-05 · 状态：步骤 01–09 已完成，步骤 10 待真机与试玩

## 本地运行

已验证环境：Windows、Node **22.22.3**、npm **10.9.8**。项目限定 Node 22.12+ 的 22.x 与 npm 10，`.nvmrc` 记录本次实际版本。Vite 的 Node 兼容要求见[官方入门说明](https://vite.dev/guide/)。

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/`。开发服务只监听本机，端口被占用时会明确报错。

```sh
npm run typecheck
npm run test
npm run build
npm run preview
```

正式构建输出到 `dist/`；预览地址为 `http://127.0.0.1:4173/`。路由使用 HTML5 history；未来部署时需把应用路径回退到 `index.html`。当前没有执行部署。

依赖已精确锁定，并生成 `package-lock.json`：Vue 3.5.43、Vue Router 4.6.4、Vite 8.3.2、Vue 插件 6.0.9、TypeScript 5.9.3、vue-tsc 3.3.12、Node 类型 22.20.5，测试用 fake-indexeddb 6.2.5。使用 Vue Router 4 与 TypeScript 5.9 的已选定兼容组合；后续安装用 `npm ci` 复现本次依赖。

## 当前实现范围

首页、创造工坊、我的海洋、两个钓场、图鉴、设置已接通，支持导航、工坊分类和图鉴分区切换；无效地址提供返回首页入口。页面使用 HTML 控件、可见键盘焦点、跳到主要内容链接和响应式布局。游戏模块按页面延迟加载。

工坊已接入独立鱼文档与共享 Canvas 2D 渲染器：1 种流线身体、分叉/扇形两种尾巴和默认鳍眼嘴；身体长度 0.75–1.4、高度 0.7–1.3、头部占比 20%–40% 可通过滑块或键盘调整。头色裁剪在同一身体轮廓内；部件按规范坐标和轮廓锚点随变形连接。恢复默认比例保留尾巴和其他设计字段，切换工具分类保留当前造型。固定工坊视角避免自动缩放抵消长度变化，转屏时重绘适配画布。

步骤 03 新增普通画笔（12 色、可调粗细，笔迹裁剪在身体内、随比例伸缩）、只读试游，以及 IndexedDB 单草稿自动保存：改动后 500ms 保存，切页前等待保存，刷新后恢复造型和笔迹。保存失败或存储不可用时保留当前作品并提示，离开前会确认。钓鱼、作品入海和备份尚未实现；首页、海洋等页面仍是明确标记的静态示范插画。步骤 04 按拼接契约重做了鱼模型：5 身体、5 头型、6 尾、6 套鳍、5 眼、5 嘴可以任意组合，并补齐 12 色、10 花纹、发光笔、橡皮、换底色、6 种印章、30 步撤销重做、随机预览、清空确认与暗背景预览。开发时可打开 `http://127.0.0.1:5173/dev/parts` 查看部件组合总览（正式构建不包含）。

步骤 05–06 打通了从创造到海洋：试游 15 秒后看游动风格，取名、选性格和喜爱区域，组合彩蛋可开关，保存后鱼游进“我的海洋”。海洋里可以点选、收起/展示、再次编辑（更新或另存）和删除，最多保存 30 条、同屏 20 条。设置页可以导出完整备份；导入前先校验并预览，确认后整体替换。存储不可用时可以导出临时作品。步骤 07–09 加入了钓鱼和两种玩法之间的联系：
- **钓鱼**：两个虚构钓场，各 6 种已核实来源的真实鱼类；选饵、选落点、等咬钩、提竿、按住收线，然后放生；可以开辅助模式，也可以用键盘。
- **图鉴**：分“海洋发现”和“我的创造”两区，未发现的鱼显示剪影。
- **两种玩法的联系**：钓到的新物种可以把配色带进工坊（可撤销），可以邀请到海洋里做客；喜欢这片钓场的原创鱼偶尔会路过打招呼。
- **设置**：提示音、辅助操作、减少动态三个开关，以及清空全部数据（需要两次确认）。

步骤 10 已完成桌面与模拟环境的验收，结果见实施计划 2.10；iPad 真机、读屏软件和亲子试玩还没做，完成之前不称为完整 MVP。

类型检查、正式构建、正式构建的设置页直达，以及浏览器中的页面导航/刷新、工坊与图鉴切换、键盘操作已验证。六页面在 390×844、768×1024、1366×768 的浏览器视口下没有横向溢出，所检查的操作控件高度均至少 44px。真机触摸、iPad 性能和全部玩法验收仍待后续执行。

`npm run test` 使用 Node 内置测试运行器，当前 60 项，覆盖全部 22,500 种部件组合的拼接检查、坐标逆变换、试游与游动风格、彩蛋规则、海洋巡游、撤销历史、草稿与作品事务、备份校验与回滚、钓鱼状态机与帧率无关性、成功耗时模拟、捕获幂等、偶遇独立随机流和 12 种物种资料；存档测试使用开发依赖 fake-indexeddb。规则测试、类型检查及构建通过，浏览器已检查极值调整、鼠标拖动、键盘操作、工具切换和三个目标视口。尚未测量 <100ms 响应目标，也没有真机触摸或 iPad 性能结论。

本地验证截图和视口记录位于 `.verification/`，不纳入 Git。阶段验收详见实施计划第 2.4–2.5 节。

## 已确定的方向与建议决策

| 类型 | 内容 |
| --- | --- |
| 用户明确要求 | 丰富拼装和涂色的可玩性；造鱼与钓鱼独立，又能产生联系；先完成文档，再分步实现，当前已执行步骤 01–09，步骤 10 部分完成；部件改为拼接式，身体、头型、尾、鳍、眼、嘴分别选择 |
| 本文建议的产品基线 | 首个完整 MVP 同时包含造鱼、钓鱼、我的海洋；允许先交付内部造鱼切片，但不把它称为完整 MVP |
| 本文建议的工程基线 | 2D、浏览器本地优先；无现有工程时采用 Vue 3 + TypeScript + Vite + Canvas 2D + IndexedDB |
| 已核对 / 仍待核对 | 工程和依赖已初始化并验证；可编辑素材、真实鱼内容来源及实测设备在后续对应步骤核对 |

优先级以 PRD 为准，数据与行为契约以技术文档为准；发生冲突先记录并更新文档，再改实现。所有时长、概率、数量上限和性能数字都是初始设计或验收目标，不是实测结果。不得把游戏中的性格、游速公式和组合特效写成生物学结论。

## 本轮有意收敛的内容

上一轮概念方案中“完整 MVP 含钓鱼”和“V1.5 再做钓鱼”存在口径差异，本文已统一为：M1 是内部造鱼验证，M3 才是双玩法完整 MVP。材料和基础颜色从开始就可用；钓鱼仅增加灵感推荐。深海、公共海洋、每日任务、成长解锁与鱼之间的长期关系进入后续候选，不进入首版验收。
