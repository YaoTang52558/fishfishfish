## 4. 完成定义

每个开发任务需说明完成的需求 ID、运行方式、已执行验证、未验证项和剩余限制。纯规则、存档和端到端关键流程通过；真实 iPad 验证尚未完成时必须明确标记，不能说“已支持所有设备”。

最终完整 MVP 还需满足：从空存档分别完成两个玩法；一条自绘鱼跨页面、刷新、备份恢复始终一致；没有首次创作必须钓鱼的门槛；所有真实鱼内容审核完成；性能数据有设备与场景记录；开发说明与锁文件齐全。

部署是否执行取决于后续用户开发任务和项目规范。本轮文档交付不创建站点、不发布应用。

## 5. 主要风险与处置顺序

| 风险 | 先做的验证 | 失败时的处置 |
| --- | --- | --- |
| 自由绘画在变形后失真或错位 | M0 完成 A03/A06 | 修正坐标和裁剪；先保留线性塑形，延后非线性捏脸 |
| 触屏描画误滚动、离开后输入卡住 | M0 iPad 画笔与 pointercancel | 缩小手势捕获范围，提供按钮替代 |
| 撤销或纹理消耗过大 | 30 步笔迹+20 鱼内存测量 | 差分历史、缓存淘汰、粒子降级 |
| 科普内容不准确 | M2 逐项来源核实 | 缩短事实文案并审核；不靠生成补齐未经核实的数据 |
| 张力机制对低龄过难 | 固定 seed 与 5–8 组亲子试玩 | 调时间、安全区与提示，保持辅助模式 |
| 玩法联系变成强制刷材料 | 每次集成重跑 A01/A02/A20 | 删除前置门槛，保留可选灵感 |
| 本地存档误被当作云同步 | 设置文案与跨设备检查 | 清楚说明本地范围，优先备份；云同步另立需求 |
