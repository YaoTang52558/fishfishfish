## 打开平板试玩版本

电脑和平板连接同一 Wi-Fi。在仓库根目录运行：

```powershell
npm run build:3d-preview
npm run preview:3d
```

平板 Safari 打开 `http://电脑的局域网IPv4:4174/preview/fishing-3d`，岩礁入口加 `?habitat=coastal-rock`。2026-10-06 准备时本机 WLAN 地址曾为 `192.168.1.132`，这不是固定服务地址；每次用 `ipconfig` 核对 WLAN IPv4，并保持预览命令运行。若无法访问，先检查是否同一网络，再核对 Windows 对本机 Node 服务的局域网权限；不要开放公网端口。

这是压缩后的候选构建；开发服务器的未压缩模块不能作为首包验收依据。只有候选构建的「去钓鱼」导航和 `/fishing/:habitatId` 使用 3D，便于完整试玩；正常正式构建的入口切换仍等待下面的证据。该端口对应独立存档来源：它不会看到 `5173` 的存档；试玩可从空档开始，或在设置中导入已有备份。

## 连续 60 秒性能

1. 填写型号、系统版本、Safari 版本、日期、是否接电、是否省电。竖屏和横屏各测一次，两钓场分别留记录。
2. 关闭教学，使用普通动态、保持默认自动画质，展开页面下方「试玩验收记录」，填写测试设备，点「开始 60 秒记录」。收起检查区并实际抛竿、提竿、收放线、抄起与放生；保持前台，测量中不旋转屏幕、不暂停。系统／应用「减少动态」会在空闲时停止渲染，应另外做功能检查，不把空闲停帧当成普通动态的 60 秒性能记录。
3. 满 60 秒后展开记录，点「导出本次记录」，通过 Safari 下载菜单保存 JSON。记录冻结后仍可继续玩。若中断次数不是 0，重新测一次；不要删除失败样本。
4. 帧预算：平均 ≥30fps、P95 ≤50ms、最大绘制 ≤80 次、最大三角形 ≤150,000。自动轻量档允许通过，仍需实际操作和知识／存档验收；页面「帧预算达标」不表示整项 G5 已通过。设备名称由人填写，JSON 不验证硬件型号。
5. 再测一次手动标准／轻量，观察鱼线和落点是否可辨、按住的收线是否连续。质量只降低 DPR、水光和水花装饰，不改变固定步、难度或奖励。

## 冷启动和真实操作

冷启动须新空缓存或关闭缓存的实测会话，限制下载 10Mbps，记录导航开始到钓场可操作的时长，目标 ≤5 秒；首场代码和资产合计 ≤4MiB。局域网快加载不算 10Mbps 证据。具备 Safari 远程检查／可控网络时才填写限速通过，否则保持待验收。截图或网络日志写明是否关闭缓存、限速、延迟、入口、计时起止。12 个 GLB 合计约 0.90MiB，每场只预载 6 个，单鱼 ≤8k 三角形；纹理 512×256，每场六张 RGBA 估算 3MiB（GPU mipmap 约 4MiB），不是全浏览器内存实测。

逐项操作，分别记录「通过 / 失败 / 未测」和现象：

- 关闭／跳过教学后能抛竿；咬钩时重看教学，等 6 秒再关，窗口和当前一竿仍在。手动暂停后重看教学，关闭仍保持暂停。
- 两指同时按收线＋左右控竿；相反控竿同时按下方向抵消。松开一个手指不会松开另一个。移出按钮、系统取消触摸、回到主屏、重新前台、旋转屏幕时无粘住输入。
- 竖屏和横屏提示／鱼线／落点／鼓轮可辨；按钮至少 44×44 CSS 像素。放大页面、较大字体仍能滚动阅读；操作区停靠底部不遮住必读提示。
- 默认静音；打开声音后提竿／收放线提示可闻，暂停和后台无声音。系统「减少动态」下鼓轮保持静态，文字仍表示收线，能完成一轮。
- VoiceOver 阅读教学标题／正文、张力／体力／收线状态和知识卡；能关闭教学并完成可访问的切换式收线。实际读屏体验由真机填写。
- 新捕获保存→放生→刷新→图鉴可找回；重复捕获只增加一次；已有备份在当前来源导入／导出后作品和两层笔迹保留。存储失败时有重试入口。
- 同一页面切换两钓场或进出 20 次，留意卡顿、发热、浏览器刷新、显卡中断。模型失败可继续简化画面，同一轮不重抽鱼。

## 5–8 组亲子试玩

每组先预留 8–12 分钟，根据完整双玩法体验适当延长。记录组号及年龄段即可，无需姓名或儿童影像。首次体验可用新的浏览器配置／隐私会话，或在已有会话用控制台只删 `fish-fishing-tutorial-v1`（不要清空作品／图鉴）；仅关闭重开普通标签页不会重置 localStorage。先自由选择造鱼或钓鱼，再体验另一个入口，让孩子自己看教学和玩，家长只在卡住时帮助；辅助开关与是否成人代操作须记下来。

记录首作和首次钓鱼成功所需时间、试游后是否回改、能否找回自己的鱼、在哪里误操作、是否能说清「鱼发力时松线」、是否知道放生后图鉴还保留、是否主动提出再玩。将造鱼结果写在「误操作与卡点」栏或附注，钓鱼成功时间单独填写。问题发生后记具体按钮／提示／阶段，先修阻断问题再决定入口替换。此小样本用于发现问题，不作为统计教育效果结论。
